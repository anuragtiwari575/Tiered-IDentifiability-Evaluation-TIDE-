# TIDE — Tiered IDentifiability Evaluation

Analysis code for *Distance, Not Time: Anatomical Correspondence Governs Patient Identifiability
in Brain MRI Encoders*.

TIDE measures how much patient identity a frozen image encoder retains, resolved by the distance
between an evaluation slice and the nearest probe-fit slice and by the separation between
acquisitions, at a fixed probe budget and against raw-pixel and random-encoder floors. This
repository holds every script used in the paper, the scripts that rebuild every table and figure,
and the analysis outputs those tables and figures are built from.

Repository: <https://github.com/anuragtiwari575/Tiered-IDentifiability-Evaluation-TIDE->

> Paper status: under review. Citation details will be added on acceptance.

## What is and is not here

Included: all analysis code, the stored analysis outputs in `results/`, and the scripts that
regenerate the paper's tables and figures from them.

Not included, by design:

- **The OASIS images.** OASIS-1 and OASIS-2 are distributed by the Open Access Series of Imaging
  Studies under its own data-use terms. Obtain them from the OASIS project directly; this
  repository redistributes no imaging data.
- **`linkage_candidates.csv`.** The cross-release linkage analysis writes a candidate list that
  associates participant identifiers across two releases of the same people. It is deliberately
  not shared. The paper and this repository report aggregate counts only, and the data-use terms
  forbid attempting to identify participants.
- **Feature caches.** The `.npy` encoder features are large and are regenerated by the pipeline.

## Reproducing the paper's tables and figures

The stored outputs in `results/` are enough to rebuild every table and figure without re-running
the pipeline or obtaining the images:

    python tables/source/make_tables.py results tables
    python figures/source/make_figures.py results figures

No number in the paper's data tables is typed by hand; each is parsed from `results/`.

## Running the full pipeline

Requires the OASIS-1 and OASIS-2 archives. Run from the directory holding the scripts, in this
order. Each step writes its outputs to a directory that the next step reads.

1. `build_index.py` — index the raw OASIS scans
2. `cache_slices.py`, then `encode_slices.py` — slice cache, then 32 frozen encoders plus the
   pixel floor (`extract_features.py` holds the shared slice reader)
3. `tide_run.py` — OASIS-1 T88 caches, controls, SIA-mode baseline, identity-supervised positive
   control
4. `tide_regrid.py` — distance-to-nearest-fit binning. This supersedes `run_tiers.py` and
   `tide_grid.py`, which binned by nominal offset; both are kept because the nominal-offset output
   is what the paper's artefact panel (Fig. 3a) is drawn from
5. `tide_full_oasis2.py --ncc-min 0.45` — OASIS-2 raw and own registration, probes, statistics
6. `tide_time_matched.py` — time effect at matched pool size
7. `tide_extras.py` — privacy–utility, verification metrics, cross-release linkage audit,
   identity correlation length
8. `link_threshold_audit.py --cache-root . --out tide_extras` — linkage counts across threshold
   rules, with the demographic concordance of each linked set
9. `time_cluster_bootstrap.py --cache-root . --out tide_time_matched` — participant-clustered
   bootstrap of the time slope, fitted within OASIS-2

Sanity checks, runnable at any point after step 1: `check_t88_pairs.py`, `check_registration.py`.

## Requirements

Python 3. The pipeline needs a GPU for the encoding step; everything downstream runs on CPU.

    pip install -r requirements.txt

`requirements.txt` lists the packages without pins. Replace it with the exact versions used for
the published run before archiving this repository:

    pip freeze > requirements.txt
